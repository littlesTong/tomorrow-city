# 明日城市：从上架到收款的完整链条

核对日期：2026-09-16。价格、分成和平台规则会变，上线前以 App Store Connect 当时的页面为准。

## 先说结论：下载量本身不赚钱

免费 App 被下载一次，Apple 不付给你任何钱。收入只有三种来源：付费下载（买断价）、App 内购买（IAP）、广告。所以"下载量有没有收益"要换算成：下载 → 留下来玩 → 其中一小部分人付费或看广告。

一个粗算框架（数字是假设，用来理解量级，不是预测）：

| 环节 | 假设 | 1,000 次下载的结果 |
| --- | --- | --- |
| 付费玩家比例 | 2%（免费游戏付费率通常是个位数百分比） | 20 人 |
| 人均消费 | 3 美元 | 60 美元流水 |
| Apple 抽成 | 15%（小型企业计划） | 到手约 51 美元（未扣税） |
| 激励视频广告 | 美国 iOS 平均 eCPM 约 19.6 美元 / 千次展示 [MAF] | 300 个活跃玩家每人看 3 次 ≈ 18 美元 |

结论：1,000 次下载大约是几十美元，1 万次是几百美元，10 万次才开始接近稳定小额现金流。开发者年费是 99 美元。气候政策模拟属于小众品类，自然流量不会很大，**决定收入的是获客和留存，不是付费按钮本身**。

## 关于你提的定价：复活 10 美元、补给 1 美元

机制方向对（失败后复活、活着时补给都是成熟的消耗型 IAP），但 10 美元复活大概率卖不动：

- 休闲游戏里的单次消耗品，常见价格档是 0.99–2.99 美元。10 美元已经是很多人买一整款买断游戏的价格，玩家刚输掉一局时的冲动消费上限远低于这个数。
- 更可行的组合：
  - **复活 1.99 或 2.99 美元**（消耗型）。
  - **紧急补给 0.99 美元**（消耗型，每年最多一次，代码已限制）。
  - **每局 1 次免费复活，看一段激励视频**。这能让不付费的玩家也产生收入，也会让付费复活显得"值"。
  - **4.99 美元一次性"城市剧本包"**（非消耗型），就是原计划里的三座付费城市。买断型内容对教育类玩家更友好，也更稳定。
- 用 App Store Connect 的价格档先上 1.99 / 0.99，上线后按实际转化再调。先定低价再涨，比先定高价没人买更容易调整。

**设计上的一个提醒**：游戏里的"死亡"是人口指标，复活付费本身合规，但如果补给强到"不付钱就活不下去"，评价会迅速变差，教育场景（老师、学校）也会排斥。现在的数值是：免费高手玩家约 90–100 年，复活一次多撑约 15–20 年，补给只是缓冲。建议保持"付费让你走得更远，不付费也能完整体验"。

## 完整链条（按顺序）

### 1. 身份与账号（你本人完成）

1. 注册 Apple Developer Program，个人身份 99 美元/年。个人账号的 App Store 卖家名会显示你的法定姓名；想显示工作室名需要注册公司并申请 D-U-N-S 编号。
2. **如果你持学生签证在美国，开始产生收入前先问学校国际学生办公室**，个人经营收入可能受签证身份限制。这是需要确认的法律问题，我不是律师。
3. 在 App Store Connect → 协议、税务和银行，签署"付费 App 协议"，填银行账户和税表。没签这个协议，IAP 商品无法上线，沙盒测试也会受限。
4. 申请加入 App Store 小型企业计划：上一年净收入低于 100 万美元时，抽成从 30% 降到 15%；新开发者也可以加入 [Apple]。

### 2. 本地工程（已完成大部分）

- 网页游戏在 `dist/`，Capacitor 把它打包成原生 iOS 工程，放在 `ios/App`。
- 支付走 `@capgo/native-purchases`（StoreKit 2）。浏览器里运行时是**测试模式，不扣钱**，按钮上显示"测试"。
- 在你的 Mac 上：安装 Xcode 和 Node.js → 进入 climate-city 目录运行 `npm install` → `npx cap sync ios` → `npx cap open ios` → 选模拟器运行。

### 3. 在 App Store Connect 创建商品

1. 创建 App 记录，Bundle ID 与 Xcode 一致（现在是占位的 `com.example.tomorrowcity`，必须改成你自己的，比如 `edu.tong.tomorrowcity` 这类唯一 ID）。
2. 新建 App 内购买：
   - `tomorrowcity.revive`，类型"消耗型"，城市复活。
   - `tomorrowcity.supply`，类型"消耗型"，紧急补给。
   - （可选）`tomorrowcity.cities`，类型"非消耗型"，剧本包。
3. 每个商品填中英文名称、描述、价格档、审核截图。第一个版本的 IAP 需要和 App 一起提交审核。

### 4. 测试付款

1. Xcode 里加 StoreKit Configuration 文件做本地测试（不走 Apple 服务器）。
2. App Store Connect → 用户和访问 → 沙盒测试员，用沙盒账号在真机测试：购买成功、取消、网络中断、连续点击。
3. TestFlight 发给 5–20 个朋友试玩，观察他们玩多久、在哪一年崩塌、是否点复活。

### 5. 提交审核时容易被拒的点

- **4.2 最低功能**：纯网页套壳容易被拒。现在已经有底部标签栏、原生内购、离线运行，还要确保不出现网页链接跳转、下拉回弹之类"像网站"的表现。
- **3.1.1**：数字道具必须用 Apple IAP，不能引导去网页付款。
- **隐私**：没有接广告和统计 SDK 时，隐私问卷可以填"不收集数据"。接入广告 SDK 后要重新填写，并加 App Tracking Transparency 弹窗。
- 需要一个公开的隐私政策网址和客服网址（GitHub Pages 就够）。
- 中国大陆区需要版号，首发先不勾选中国大陆。

### 6. 钱怎么到账

用户付款 → Apple 扣除分成和部分地区的税 → 按财务月结算，满足最低付款额后打到你的银行账户，通常在财务月结束后约一个多月到账。App Store Connect 的"付款和财务报告"能看到明细。

### 7. 让现金流"稳定"的做法

单次付费靠运气，稳定收入靠这几件事：

1. **留存**：每日挑战（全球同一个随机种子，比谁撑得久）、排行榜（区分"无复活"和"有复活"成绩）、成就。玩家每天回来，广告和补给才有持续收入。
2. **内容更新**：每 1–2 个月加一座新城市或一个新冲击事件，更新本身就会带来一波回流。
3. **获客**：
   - App Store 关键词优化（ASO）：标题和副标题里放"气候、城市、策略、模拟"。
   - 短视频展示"这座城市 2077 年崩塌"的过程，这类内容有传播性。
   - 教育渠道：环境经济学课程、中学地理或科学老师。这是你相对别人最有优势的渠道。
4. **教育授权（可能比 IAP 更稳）**：面向学校和课程，推出无广告、无内购的教学版，按班级或学校收费，或者申请科普和教育类资助。气候教育类产品走这条路常常比靠玩家冲动消费更可持续。

### 8. 上线后看的数据

按顺序看，前一个不达标，后面的都不用优化：

1. 次日留存 / 7 日留存：玩家有没有回来。
2. 首局完成率：多少人玩到城市崩塌。
3. 复活弹窗点击率 → 购买转化率。
4. 每日活跃用户平均收入（ARPDAU）× 日活 = 日收入。

需要接一个统计工具才能看到这些数据（例如 TelemetryDeck，隐私友好）。接入后要更新隐私声明。
